# 开题前必做清单

> 目标不是“把文档写长”，而是在开题当天能够证明：**问题真实、文献查重充分、算法差异明确、数据可得、实验能做、计划可执行。**  
> **执行时间表**：[[01-论文/开题/开题冲刺计划-至0910]]（截止 2026-09-10）

## 0. 北京科技大学公开校级要求（先核对）

- [ ] 硕士书面开题报告按 **0.5～1.0 万字**准备
- [ ] 阅读、分析和总结近 15～20 年相关文献，硕士一般不少于 **40 篇**
- [ ] 报告包含：课题来源、选题依据、国内外现状、目标、内容、关键问题、创新点、方法、技术路线、实验、研究基础、风险措施和计划
- [ ] 确认书面报告与口头汇报的具体要求
- [ ] 确认学院是否有独立模板、文献数量、PPT 时长或评委要求
- [ ] 先在研究生信息管理系统提交，再下载打印《研究生开题报告及文献总结评审表》
- [ ] 向学院确认开题与答辩的最短间隔及当前适用规定

> 公开规则只解决校级底线；学院和导师要求可能更严格，必须以最新通知为准。

## 1. P0：不完成就不建议开题的事项

### 1.1 行政与题目确认

- [ ] 确认自己的学位类型：学术型 / 专业型
- [ ] 获取学院最新开题模板、评审表、截止日期和提交方式
- [ ] 与导师确认最终中文题目
- [ ] 与导师确认课题性质：应用基础研究 / 工程技术研究 / 其他
- [ ] 确认是否需要企业导师、校外专家或数据证明
- [ ] 确认开题汇报时长、PPT 页数建议和提问时长

**给导师确认的一句话版本：**

> 本课题拟针对招聘多轮对话中意图不确定、事实证据不足和错误代价不对称的问题，提出证据门控的风险敏感决策算法，统一选择回答、澄清或拒答，并在脱敏真实业务数据上对比验证。

### 1.2 数据授权与伦理合规

- [ ] 明确谁有权批准业务数据用于学位研究
- [ ] 获得书面或可追溯的数据使用授权
- [ ] 确认数据只能公司内运行还是允许产生脱敏样本
- [ ] 确认论文能公开哪些统计量、案例和实验结果
- [ ] 编写脱敏规则：姓名、手机号、邮箱、身份证、微信号、公司/岗位敏感字段
- [ ] 明确不使用性别、年龄等受保护属性作候选人录用判断
- [ ] 向学院确认是否需要伦理审查或数据合规说明
- [ ] 制定数据泄露应急与删除机制

> 如果数据授权无法落实，必须提前准备公开数据集/合成数据作为替代方案；不能等开题后才发现数据不可用。

### 1.3 文献与创新性查重

- [ ] 建立 Zotero/EndNote 文献库
- [ ] 累计不少于 40 篇正式文献
- [ ] 其中近 3～5 年文献占主体，同时保留 POMDP/DST 经典文献
- [ ] 至少精读 10～15 篇核心论文
- [ ] 为每篇核心论文记录：问题、输入输出、算法、数据、基线、指标、局限
- [ ] 完成相关工作对比表
- [ ] 专项检索 2024—2026 年：`evidence-gated clarification`、`risk-sensitive dialogue`、`uncertainty-aware dialogue planning`、`recruitment dialogue`
- [ ] 明确 EG-RSD 与 CICC、UoT、INTENT-SIM、SAGE、Naive RAG 的逐项差异
- [ ] 找到至少 3 篇中文核心/学位论文用于国内研究现状
- [ ] 所有引用通过 DOI/ACL Anthology/出版社页面核验，禁止使用 AI 虚构参考文献

**创新性放行条件：**

> 尚未发现已有方法同时具备“多轮信念 + 证据改变动作可行域 + 业务不对称代价 + 回答/澄清/拒答统一决策”，或即使存在相似框架，也能明确指出本研究的新目标、新推导或新算法步骤。

### 1.4 算法必须达到“可写伪代码”的程度

- [ ] 定义状态 \(h_t,z_t,b_t,\mathcal{E}_t,s_t\)
- [ ] 定义回答、澄清、拒答/转人工动作
- [ ] 写出信念更新公式
- [ ] 写出证据充分度的可操作定义
- [ ] 写出三个动作的风险函数
- [ ] 写出最终动作选择公式
- [ ] 写出完整伪代码
- [ ] 推导回答与澄清的切换条件
- [ ] 至少形成一个待证明命题：单调性 / 门控安全性 / 固定阈值退化关系
- [ ] 明确 LLM API 在算法中的角色，防止“算法就是 Prompt”

### 1.5 最小可行性实验

开题前不必完成整篇论文实验，但至少要证明路线能跑通：

- [ ] 从脱敏数据中抽取一个小型代表性样本集
- [ ] 建立 5～10 个招聘主意图和 3～5 类事实风险的初版 taxonomy
- [ ] 跑通裸 LLM、固定阈值、Naive RAG 三个最小基线
- [ ] 验证 API 能稳定输出结构化候选意图
- [ ] 验证知识库能返回可追溯证据 ID
- [ ] 人工检查证据充分度分数是否与真实支持关系相关
- [ ] 跑通回答 / 澄清 / 拒答三动作选择
- [ ] 保存 10～20 个正反案例，能在开题答辩中展示
- [ ] 记录 API 版本、温度、Prompt、费用和延迟

**最小实验放行条件：**

> 同一批样本上，算法至少能稳定重现“高置信有证据→回答、意图不明→澄清、事实无证据→拒答”三类行为。

## 2. 业务侧需要提前拿到的材料

### 2.1 现有系统架构

- [ ] 用户入口与对话链路图
- [ ] 当前使用的模型/API 与版本
- [ ] 是否已有意图识别、RAG、规则、人工接管
- [ ] 知识库来源、更新时间与版本管理方式
- [ ] 当前系统如何记录每轮输入、输出、检索结果和动作
- [ ] 是否支持影子模式与策略回退

### 2.2 数据字典

- [ ] 会话 ID、轮次、时间、角色
- [ ] 当前/历史意图标签
- [ ] 岗位、流程、知识文档匿名 ID
- [ ] 检索文档与分数
- [ ] 模型原始回答
- [ ] 用户纠正、追问、退出、转人工
- [ ] 任务完成与问题解决标志
- [ ] 投诉/高风险错误标志
- [ ] 可用于切分数据的时间、岗位或业务单元字段

### 2.3 专家资源

- [ ] 至少确定一名熟悉招聘业务规则的审核人
- [ ] 约定争议标签如何仲裁
- [ ] 让专家对错误代价做成对比较，而不是直接拍绝对分数
- [ ] 确定专家能否参与开题前案例核验及后续人工评测

当前初稿：[[01-论文/开题/开题报告-导师讨论稿-v2]]

### 3.2 必备图表

- [ ] 一张业务问题示例图（全部脱敏）
- [ ] 一张研究问题形式化图
- [ ] 一张技术路线图
- [ ] 一张现有方法对比表
- [ ] 一张 EG-RSD 算法流程图
- [ ] 一张实验设计矩阵（基线 × 消融 × 指标）
- [ ] 一张研究计划表

### 3.3 开题 PPT

建议控制为以下结构，具体页数以学院通知为准：

1. 标题与一句话问题
2. 招聘业务痛点与脱敏示例
3. 科学问题
4. 国内外现状
5. 现有方法缺口
6. 总体框架
7. 核心算法与公式
8. 与强基线的差异
9. 技术路线
10. 数据与实验
11. 创新点
12. 可行性、风险和计划

- [ ] 每页只传达一个结论
- [ ] 公式只保留决策主公式
- [ ] 准备 1 分钟、3 分钟和完整版本的选题陈述
- [ ] 至少完成两轮模拟答辩

## 4. 必须提前准备的答辩问题

- [ ] 你的方法与 CICC 的根本差异是什么？
- [ ] 与 UoT/INTENT-SIM 相比，为什么不是换了业务数据？
- [ ] 证据门控与普通 RAG 有何本质区别？
- [ ] 只有 API，为什么仍然属于算法创新？
- [ ] 风险代价如何确定，不是人为拍脑袋吗？
- [ ] 证据充分度由谁判定，会不会 LLM 自我证明？
- [ ] 为什么用 POMDP/信念状态，而不是简单阈值？
- [ ] 招聘数据如何脱敏，是否存在伦理问题？
- [ ] 如果真实数据无法用于论文怎么办？
- [ ] 评价指标为什么能证明业务有效？
- [ ] 算法是否会因为过度拒答降低体验？
- [ ] 如果文献中已经存在高度相似方法，你的备选创新是什么？

### 备选收缩方案

如果统一框架被认为范围过大，可收缩为：

> 面向多轮招聘意图漂移的代价敏感共形澄清算法。

该方案保留算法性，放弃复杂的生成后核验；但只有导师认为当前主线过宽时启用。

## 6. 推荐完成顺序

1. **先找导师确认题目和“EG-RSD 是否足够算法”**
2. **同步确认公司数据权限与可公开边界**
3. 获取学院模板和所有行政要求
4. 建立 40+ 文献库并完成相关工作矩阵
5. 固化意图、证据、动作、代价和公式
6. 完成最小离线原型与案例
7. 根据试验结果修改创新点，避免先写结论
8. 补全报告并制作 PPT
9. 模拟答辩，专门演练“是不是拼装”这一质疑
10. 导师确认后提交系统并打印评审表

## 7. 开题就绪定义（Definition of Ready）

只有同时满足以下条件，才建议进入正式开题：

- [ ] 导师确认题目、科学问题和主创新
- [ ] 数据授权和替代方案均明确
- [ ] 40+ 文献核验完成，未发现无法解释的同构方法
- [ ] 公式、伪代码、技术路线和实验矩阵完整
- [ ] 最小实验能跑通并有可展示案例
- [ ] 开题报告达到学校字数与学院模板要求
- [ ] PPT 和高频答辩问题准备完成
- [ ] 研究生系统提交及评审表流程确认完毕
