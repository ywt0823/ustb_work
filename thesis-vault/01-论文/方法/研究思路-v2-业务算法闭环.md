# 研究思路 v2：业务—算法—验证闭环

## 1. 研究定位

本课题不是开发一个招聘 GPT，也不是把意图识别、RAG 和 Prompt 简单串联，而是：

> 针对招聘多轮对话中“意图不确定、事实依据不足、不同错误代价不对称”的问题，提出一种**证据门控的风险敏感序贯决策算法**，统一决定当前轮应该回答、澄清还是拒答/转人工；再利用脱敏业务日志估计参数、构建评测集，并通过离线回放、影子验证和小流量实验迭代算法。

论文级框架暂沿用 **UB-CEG**；其中真正承担主创新的是：

> **Evidence-Gated Risk-Sensitive Decision（EG-RSD，证据门控风险敏感决策）**

LLM API 只负责产生语义似然、候选问题和候选回答，最终动作不由 LLM 自由决定。

## 2. 问题形式化

在第 \(t\) 轮：

- 对话历史：\(h_t\)
- 当前输入：\(u_t\)
- 隐含真实意图：\(z_t \in \mathcal{Z}\)
- 意图信念：\(b_t(z)=P(z_t=z\mid h_t,u_t)\)
- 检索证据：\(\mathcal{E}_t\)
- 证据充分度：\(s_t\in[0,1]\)
- 动作：

\[
\mathcal{A}=\{\text{answer},\text{clarify}(q),\text{refuse/handoff}\}
\]

算法目标不是最大化单轮回答率，而是最小化累积业务风险：

\[
\pi^\star=\arg\min_\pi
\mathbb{E}_\pi\left[
\sum_t
C_{\text{intent}}
+C_{\text{hallucination}}
+C_{\text{interaction}}
+C_{\text{handoff}}
\right]
\]

### 2.1 多轮信念更新

用招聘业务的意图转移先验与 API 给出的语义似然进行贝叶斯式更新：

\[
b_t(z)\propto
\ell_{\text{API}}(u_t,h_t\mid z)
\sum_{z'}T(z\mid z')b_{t-1}(z')
\]

- \(T(z\mid z')\)：从脱敏历史对话估计的意图转移关系；
- \(\ell_{\text{API}}\)：黑盒 API 的候选意图分数，可用多次采样、结构化打分或共形校准近似；
- 不输出单一“硬意图”，而是保留候选意图分布/预测集。

### 2.2 证据充分度与双层门控

证据门控分两层，避免把普通 RAG 当创新：

1. **决策前门控**：判断当前检索材料是否足以支持某类回答；不足时回答动作不可行或被施加高风险。
2. **生成后核验**：把候选回答拆成原子事实，要求事实能回指证据片段；未支持事实删除、改为澄清或拒答。

### 2.3 风险敏感动作选择

回答动作的示意风险：

\[
J_{\text{ans}}
=c_i\left(1-b_t(\hat z)\right)
+c_f\left(1-s_t\right)
+c_v V_t
\]

其中 \(V_t\) 可表示合规/敏感事实风险。

澄清动作不使用固定阈值，而计算“一轮前瞻”的预期风险：

\[
J_{\text{clarify}}(q)
=c_q+
\mathbb{E}_{y\sim P(y\mid q,h_t)}
\left[\min_a J_{t+1}(a\mid y)\right]
\]

拒答/转人工风险：

\[
J_{\text{handoff}}=c_h+c_{\text{delay}}
\]

最终动作：

\[
a_t^\star=\arg\min_{a\in\mathcal{A}_{\text{feasible}}(\mathcal{E}_t)}J_t(a)
\]

当 \(s_t<\tau\) 且问题属于事实型招聘问答时，无据回答从可行动作集剔除。

## 3. 算法革新的具体方向

### 3.1 主创新：证据可行性进入动作空间与风险函数

已有澄清算法常优化信息增益，已有 RAG 常在确定回答后再检索/校验。本研究拟把：

- “是否理解用户”；
- “是否有证据回答”；
- “答错、追问、拒答分别有多大代价”

放入同一个动作选择问题。

因此创新不表述为“加入 RAG”，而表述为：

> **由证据充分度改变最优动作边界的代价敏感决策算法。**

### 3.2 辅创新：业务代价驱动的动态决策边界

固定置信阈值不能适应不同问题：

- “这个岗位在哪个城市？”证据清楚时可直接答；
- “一定能拿到多少薪资？”即使意图明确，证据不足也应拒答/澄清；
- “我适合哪个岗位？”意图和事实边界都更复杂。

本研究拟用脱敏业务结果、专家偏好和敏感性分析确定代价矩阵，使阈值由风险关系推导，而不是人工拍一个统一常数。

### 3.3 辅助机制：多轮意图漂移下的信念更新

利用意图转移矩阵、候选集与当前证据，避免每轮独立分类。只有在相对 CICC/DST 有明确算法差异和消融收益时，才将其写成独立创新点；否则只作为主算法组件。

### 3.4 可讨论的理论性质

开题阶段至少争取给出以下命题之一：

1. **单调性**：幻觉代价上升或证据充分度下降时，最优策略的回答区域不会扩大；
2. **门控安全性**：在证据支持度低于阈值且无据回答代价高于澄清/拒答代价时，最优动作不会选择无据回答；
3. **代价边界**：推导回答与澄清的切换条件，说明固定置信阈值只是本算法的特殊情形。

> 注意：这些目前是待证明的研究假设，不应在完成推导前宣称已经证明。

## 4. 如何叠加到已有招聘业务

### 4.1 低侵入式架构

```text
用户消息
   │
   ▼
现有意图/RAG/LLM 服务 ──► 候选意图、证据、候选回答
   │
   ▼
EG-RSD 决策旁路层
   ├─ 回答（证据充分）
   ├─ 澄清（风险可通过提问降低）
   └─ 拒答/转人工（高风险或无证据）
   │
   ▼
现有发送链路 + 全量决策日志
```

先作为“旁路决策器”叠加，不立即替换现有系统：

- 可随时回退；
- 能和原策略做逐条对比；
- 能记录“原系统会怎么答、算法建议怎么做”。

### 4.2 业务数据如何转为算法要素

| 现有业务资产 | 转换后的算法要素 |
|--------------|------------------|
| 脱敏多轮会话 | 意图转移 \(T\)、信念校准集、离线测试集 |
| 岗位/JD/流程/政策知识 | 证据库与金标准证据 ID |
| 用户纠正、负反馈、投诉 | 误答/幻觉标签与风险样本 |
| 转人工、会话中断、追问轮数 | 澄清/拒答/交互代价估计 |
| 任务完成、有效留资等 | 业务效果指标（不能替代学术指标） |
| 专家审核 | 代价排序、事实支持与澄清必要性标注 |

敏感原始数据不进入 Git/知识库；只保留脱敏样本、统计量、标签规范和匿名证据 ID。

### 4.3 业务闭环

```text
失败案例/业务反馈
       ↓
脱敏 + 标注 + 错误归因
       ↓
更新意图转移 / 校准 / 代价 / 证据阈值
       ↓
离线回放 + 强基线 + 消融
       ↓
影子模式（只建议不生效）
       ↓
小流量对照验证
       ↓
新日志进入下一轮
```

## 5. 分版本迭代路线

| 版本 | 叠加内容 | 研究目的 | 关键比较 |
|------|----------|----------|----------|
| V0 | 冻结现有系统并补齐日志 | 建立业务基线 | 裸 API / 现网策略 |
| V1 | 多意图信念 + 校准 | 判断“不确定”是否可靠 | 硬分类、固定阈值 |
| V2 | 决策前/后证据门控 | 降低事实幻觉 | Naive RAG、SelfCheck |
| V3 | 统一风险动作选择 | **主算法验证** | CICC、UoT/INTENT-SIM 类 |
| V4 | 一轮前瞻澄清（VOI） | 减少无效追问 | 纯熵/固定阈值澄清 |
| V5（可选） | 根据新日志离线更新代价/策略 | 验证业务适应性 | 固定参数策略 |

论文主线做到 V3/V4 即可；V5 只有在日志字段与因果条件满足时再做，避免范围失控。

## 6. 验证设计

### 学术指标

- Intent Accuracy / Macro-F1
- ECE / Coverage（校准）
- Task Success
- Hallucination Rate / Citation Precision
- Clarification Precision、平均澄清轮数
- 累积风险 \(J\)

### 业务指标

- 用户纠正率、转人工率、会话中断率
- 有效问题解决率、流程完成率
- 高风险错误率（薪资/HC/政策错误）

学术结论不能只使用转化率，因为转化受到渠道、岗位供需等大量混杂因素影响。

### 核心假设

- H1：在相同任务成功率下，EG-RSD 的累计风险低于固定阈值澄清与 Naive RAG；
- H2：在相同幻觉率上限下，EG-RSD 的平均澄清轮数更少；
- H3：多轮信念更新在意图漂移/指代测试集上优于逐轮独立分类；
- H4：证据门控对高风险事实问题的收益显著高于一般闲聊问题。

## 7. 必须控制的边界

1. **创新性尚是候选结论**：需系统检索后才能确认没有与 EG-RSD 高度同构的近期工作；
2. **不能仅靠 LLM 自评证据**：必须有证据 ID、人工抽检或独立蕴含指标；
3. **代价不能拍脑袋**：用业务频率、专家成对偏好和敏感性分析共同确定；
4. **招聘属于高影响场景**：不得让算法使用性别、年龄等受保护属性进行差异化决策；研究对象是对话质量，不是候选人录用判断；
5. **先离线与影子验证**：避免实验性算法直接向求职者输出高风险信息。

## 8. 当前最简研究主线

如果继续收窄，最终论文只需回答一个问题：

> 与固定阈值澄清和“检索后直接生成”相比，将证据充分度与招聘业务代价写入多轮动作决策，能否在不增加过多追问的情况下显著降低误答和幻觉？

这条主线规模适中、可实验、可消融，也最符合“算法革新并回归业务验证”的要求。
