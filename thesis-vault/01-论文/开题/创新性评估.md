# 创新性评估：当前方向是否具备硕士应有创新性

> 结论先说：**方向可行，但按「三模块串联」写会偏弱；必须把创新收成 1 个主算法贡献 + 1 个形式化性质 + 业务验证，才更像学院派硕士课题。**

## 1. 硕士创新性的现实标尺（软院/学院派）

通常不要求发明新基座大模型，但至少满足：

| 维度 | 及格线 | 优秀线 |
|------|--------|--------|
| 问题形式化 | 有符号、有目标函数 | 有可分析的性质/边界条件 |
| 方法 | 相对强基线有明确差异 | 差异可消融、可复述为算法步骤 |
| 实验 | 自建/脱敏数据 + 多基线 | 消融 + 人工评测协议 |
| 贡献表述 | 不是「应用了 GPT」 | 不是「拼了三个现成模块」 |

导师已明确要**算法革新** → 单纯「招聘场景落地」或「Prompt/Agent 工程」**不够**。

## 2. 当前方向的真实处境

### 已有成熟工作（会挤占创新空间）

- 澄清何时问：CICC、INTENT-SIM、UoT、SAGE-Agent、ClarifyAgent…
- 不确定量化：Semantic Entropy、共形预测…
- 抗幻觉/证据：RAG attribution、SelfCheckGPT…
- 招聘对话：SimRPD、面试槽填充等（偏系统/数据）

因此：**单独做「澄清」或单独做「RAG」创新性不足**；开题若写成「我们把它们用在招聘」，学院派很容易判为工程集成。

### 仍然站得住的切口（有条件成立）

在招聘场景中，三类代价高度不对称且同时存在：

1. **意图误判代价高**（推错岗位/流程 → 转化与体验双杀）
2. **事实幻觉代价高**（薪资/HC/政策说错 → 合规与信任风险）
3. **过度澄清也有代价**（流失、体验差）

多数已有算法优化的是「信息增益」或「覆盖保证」，**很少把「无证据不得承诺」写进同一动作选择目标**，也很少在**多轮意图漂移**下做代价敏感策略。

→ 创新必须落在：**代价敏感的序贯决策（含证据门控动作）**，而不是三个模块的物理拼接。

## 3. 创新性评级（自评）

| 写法 | 评级 | 答辩风险 |
|------|------|----------|
| A. 招聘 GPT 助手 + 业务指标 | ❌ 不足 | 「没有算法」 |
| B. UB-CEG = Belief + Clarify + RAG 流水线 | ⚠️ 偏弱 | 「拼装创新」 |
| C. 形式化风险目标 + 可计算策略 + 相对强基线的算法差异 + 小性质讨论 | ✅ 达标（推荐） | 可控 |
| D. 新网络结构/新预训练 | 不现实 | API 约束下做不到 |

**当前草案若停在 B，创新性勉强够开题、不够安心答辩；必须推向 C。**

## 4. 建议「收束」后的单一主创新（写进开题）

### 主创新（只打这一拳）

**提出面向高代价对话的证据门控风险敏感决策算法（EG-RSD / 或沿用 UB-CEG 但改表述重心）**：

在部分可观测意图信念 \(b_t\) 下，动作集显式包含「无证据回答」，并定义：

\[
a_t^\star = \arg\min_{a \in \mathcal{A}} \mathbb{E}_{z\sim b_t}\big[R(a,z)\big] + \lambda \cdot \mathrm{Cost}_{\mathrm{clarify}}(a)
\]

其中对事实性回答动作，若证据支持度 \(\mathrm{supp}(a,\mathcal{E}_t)<\tau\)，则风险取高惩罚（或直接从可行动作集剔除）。澄清动作用信息增益/共形集缩小信念。

**一句话差异：**

> 已有工作多把「问什么」与「答得是否有据」分开优化；本算法将证据可行性嵌入动作空间与风险，使澄清/回答/拒答在同一决策准则下选择。

### 辅创新（最多一条，别贪）

- **多轮招聘意图信念更新协议**（意图漂移、指代、槽位）——偏方法设计  
或  
- **在简化假设下的策略性质**（如：证据不足时最优动作必为澄清或拒答；共形覆盖与风险上界关系）——偏理论味道，学院派加分

### 明确不宣称的创新

- 新 LLM 架构、新注意力、全量微调方法  
- 「首次研究澄清/幻觉」（文献已很多）

## 5. 创新性达标的最低交付物（开题就要承诺）

1. **形式化**：状态、动作、风险、证据约束（1–2 页公式）  
2. **算法伪代码**：BeliefUpdate / ActSelect / EvidenceGate（可实现、可消融）  
3. **强基线对比**：至少含 CICC 或阈值澄清、UoT/INTENT-SIM 类、Naive RAG、裸多轮 LLM  
4. **消融**：去掉风险项、去掉证据门、去掉多轮信念  
5. **性质讨论**：至少 1 个命题级讨论（不必强证到顶会深度）  
6. **脱敏招聘数据**上的主表 + 人工评测协议  

缺 1/3/4，创新性叙事会塌。

## 6. 主要风险与对冲

| 风险 | 对冲 |
|------|------|
| 被说拼装 | 开题创新点只写「统一风险决策」，模块当实现手段 |
| API 换模型结果漂 | 冻结模型版本；多模型敏感性附录 |
| 标注贵 | 先小精标集 + 模拟用户；协议写清 |
| 导师要更「理论」 | 加重共形/风险上界一节 |
| 导师要更「业务」 | 加重误答代价定义与业务指标映射 |

## 7. 最终判断（给自己/导师）

- **是否具备硕士创新潜力：有，但是有条件的。**  
- **条件：把故事从「招聘里用了先进 LLM 技术」改成「提出证据门控的风险敏感多轮决策算法，并在招聘脱敏数据验证」。**  
- **若不愿做形式化与强基线消融，建议换更窄的算法点（例如只深挖共形澄清在多轮招聘意图漂移上的扩展），否则创新性不够稳。**
