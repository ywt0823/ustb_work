# 选题锁定 v3 · 通用对话问题 + 招聘验证

## 一句话定位

**科学问题做通用，实验素材用招聘。**

不是「研究招聘对话」，而是：

> 研究多目标任务型对话中，在意图不确定、槽位歧义、证据不充分时，如何做代价敏感的序贯选择性决策；以智能招聘代聊 Agent 为验证场景。

## 建议题目

**主推：**

面向多目标任务型对话的证据约束风险敏感序贯决策方法——以智能招聘代聊为例

**备选：**

1. 任务型对话中的回答—澄清—弃权序贯选择性决策算法研究
2. 基于意图信念与证据门控的多目标对话策略优化方法
3. 面向高风险任务型对话的不确定性感知动作选择算法

## 通用科学问题

在任务型多轮对话中，系统同时面临：

1. **意图部分可观测**（口语歧义、话题切换、多意图交织）
2. **槽位不完全 / 有歧义**（如「96的」）
3. **外部证据不充分**（知识库未命中仍可能幻觉回答）
4. **多目标冲突**（答疑准确性 vs 留资转化 vs 人岗匹配正确性）
5. **动作代价不对称**（错答、错匹配、过度澄清、过早要电话）

求解：在动作集合

\[
A=\{\text{执行/回答},\ \text{澄清},\ \text{弃权/转人工}\}
\]

上，基于状态 \(s_t=(b_t, z_t, e_t)\)（意图信念、槽位置信、证据充分度）选择使累计业务风险最小的策略 \(\pi\)。

## 招聘只是验证域的原因

| 招聘业务事实 | 对应的通用对话问题 |
|--------------|-------------------|
| 中控分发三任务：匹配 / 留资 / 答疑 | 多目标任务型对话的策略切换 |
| 意图 + confidence + slots + action | 不确定感知的动作选择接口 |
| RAG 抑制答疑幻觉 | 证据约束下的可回答判定 |
| 「96的」槽位歧义 → 追问 | 歧义感知澄清 / 主动信息获取 |
| 错匹配、错答、过早要电话代价不同 | 不对称代价敏感决策 |
| 12K/min、弱模型+工程补效果 | 黑盒 LLM API 条件下的外层决策算法 |

因此论文贡献写在「通用决策算法」，招聘写在「问题实例化与实验验证」。

## 主算法（收束后）

**EG-RSD**：Evidence-Gated Risk-Sensitive Dialogue Decision

只打一拳：

> 把经典拒答/选择性预测从「预测 or 拒绝」推广为多轮「执行 / 澄清 / 弃权」，并加入证据可行域与多目标代价。

非创新（作基线组件）：

- Few-shot 意图分类
- RAG 混合检索
- Redis 会话记忆
- 多智能体框架本身
- 拟人度 Prompt

## 与现有平台的对接点

可直接从现有 Agent 协议抽象变量：

```json
{
  "intent": "...",
  "confidence": 0.92,
  "slots": {...},
  "action": "调用工具或追问"
}
```

升级为：

- `belief`：意图分布，而非单标签
- `slot_uncertainty`：槽位歧义分
- `evidence_score`：RAG 证据充分度
- `action ∈ {EXECUTE, CLARIFY, ABSTAIN}`
- `cost_matrix`：按任务类型（匹配/留资/答疑）设定

## 见导师口径

> 我做的不是招聘 Agent 系统论文，而是任务型对话中的序贯选择性决策算法。招聘代聊提供高并发、多目标、高代价的真实验证环境；算法本身可迁移到客服、政务、医疗分诊等同类对话。
