# 协作模式清单（从实战抽取）

> 每发现稳定可复用的人机协作模式，加一条。将来可变成产品功能或课程小节。

## 已识别模式

### M1 · 约束采集卡
先固定业务/数据/算力/论文口味，再谈方向。  
来源：[[06-AI协作日志/会话记录/SES-2026-07-29-方向讨论与选题收敛]]

### M2 · 算法革新重写
当导师要「算法」时，把应用叙事改写成形式化问题 + 伪代码 + 强基线对比。  

### M3 · 文献雷达
先定站点与检索词，再输出「成熟度判断 + 开题切口」，避免假创新。  

### M4 · 双轨落盘
每次会话结束同时写：论文收获 / IP 收获 / 下次输入。  

### M5 · Vault 即系统
用 Obsidian 结构把过程资产产品化，而不是散落在聊天窗口。

### M6 · 开题前创新性压力测试
先问「会被说成拼装/纯应用吗？」；强制收束为 1 个主算法贡献 + 可消融差异 + 强基线清单，再写开题创新点。  
来源：[[06-AI协作日志/会话记录/SES-2026-07-29-开题写法与创新性评估]]

### M7 · 报告完成度 ≠ 研究就绪度
AI 可以很快生成完整报告，但只有文献查重、数据授权、算法伪代码、最小实验和导师确认同时过关，才算真正具备开题条件。产品应同时展示“文档完成度”和“证据就绪度”。  
来源：[[06-AI协作日志/会话记录/SES-2026-07-29-开题报告与开题前清单]]
