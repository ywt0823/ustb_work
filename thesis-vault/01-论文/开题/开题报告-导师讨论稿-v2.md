## 摘要

随着大语言模型在企业招聘咨询、岗位推荐、招聘流程问答和候选人引导等场景中的应用，多轮对话系统已具备较强的自然语言理解与生成能力。然而，真实业务对话仍存在意图识别假自信、上下文衔接不稳定以及对薪资、岗位编制、面试流程和招聘政策等事实信息产生无依据回答等问题。上述错误在招聘场景中的代价并不对称：事实性幻觉可能引起信任和合规风险，意图误判可能导致任务失败，而过度澄清又会增加交互负担并造成用户流失。现有研究通常分别处理意图不确定性、澄清问题生成或检索增强生成，尚不足以直接解决“当前是否允许回答、是否应进一步澄清、何时应拒答或转人工”这一统一决策问题。

本研究拟将招聘多轮对话形式化为部分可观测意图下的序贯决策过程，提出一种证据门控的风险敏感多轮对话决策算法。算法维护多轮意图信念状态，利用招聘知识库检索结果估计证据充分度，并将意图误判、事实幻觉、澄清交互和拒答转人工等代价纳入统一风险函数。在此基础上，算法动态选择回答、澄清或拒答动作；当事实型问题缺乏充分证据时，通过硬门控或高风险惩罚禁止无依据回答。大语言模型 API 仅承担候选意图分析、澄清问和候选回答生成等语义任务，最终动作由外层决策算法控制。

研究拟使用脱敏招聘业务对话构建标注与评测数据，采用离线回放、强基线对比、消融实验、敏感性分析和人工评测验证算法。评价指标包括意图识别准确率与校准误差、任务成功率、事实幻觉率、引用正确率、澄清有效率、平均澄清轮数及累计风险等。预期研究能够在不显著增加交互成本的情况下，降低招聘多轮对话中的高风险误答和无依据事实陈述，并为仅能调用黑盒大模型 API 的企业场景提供可解释、可插拔的可靠性增强方法。

**关键词**：大语言模型；多轮对话；意图信念；风险敏感决策；证据门控；招聘

## 一、课题来源与选题依据

### 1.1 课题来源

课题来源于本人所在企业的招聘业务实践。现有业务积累了较丰富的招聘对话、岗位信息、招聘流程和知识文档，但相关数据涉及候选人隐私与企业敏感信息，研究过程中必须经过授权、脱敏和最小化使用。本研究不以候选人筛选或录用判断为研究对象，而聚焦于招聘咨询与服务型多轮对话的意图理解、事实可靠性和交互决策。

### 1.2 业务问题

现有招聘对话主要存在以下问题：

1. **意图识别不准确**：用户经常使用省略、指代、口语和多意图表达，系统可能在证据不足时仍输出单一意图；
2. **多轮衔接不流畅**：用户可能从岗位要求切换到薪资、地点或面试流程，逐轮独立判断容易丢失上下文；
3. **事实型幻觉**：系统可能对岗位状态、薪资范围、招聘流程和政策作出知识库无法支持的陈述；
4. **决策标准单一**：现有系统通常采用固定置信阈值或直接生成，未区分不同错误在招聘业务中的代价；
5. **缺少闭环验证**：模型效果往往以通用文本指标衡量，未与用户纠正、任务完成、转人工和高风险错误等业务结果建立对应关系。

### 1.3 科学问题

本研究拟回答的核心问题为：

> 在仅能调用黑盒大语言模型 API 的条件下，如何利用多轮意图信念、检索证据充分度和业务不对称代价，统一决定系统当前应回答、澄清还是拒答，从而在控制交互成本的同时降低误答与幻觉？

这一问题不是单纯的文本生成问题，而是包含隐藏意图、不完全信息、证据约束和不同动作代价的序贯决策问题。

### 1.4 研究意义

#### （1）理论与方法意义

经典任务型对话研究以 POMDP 和信念状态处理不确定性，但在大语言模型时代，现有系统常重新退化为“输入上下文—直接生成回答”的黑盒流程。将意图信念、证据充分度与动作代价重新纳入统一决策，有助于建立适用于黑盒 LLM 的可解释外层控制方法。

#### （2）工程应用意义

方法可以作为旁路决策层叠加到现有意图识别、RAG 和 LLM 服务之上，无需修改基座模型权重，符合企业仅允许 API 调用、数据不便外流和系统需要可回退的现实约束。

#### （3）业务与社会意义

招聘属于高影响应用场景。虽然本课题不参与录用决策，但错误的岗位、薪资和流程信息仍会影响候选人的权益和信任。通过证据门控、拒答和人工接管降低高风险输出，有助于提升招聘服务的透明度与可靠性。

## 二、国内外研究现状

### 2.1 任务型对话管理与对话状态跟踪

Williams 和 Young 将口语对话系统形式化为部分可观测马尔可夫决策过程，通过信念状态同时表达多个可能的用户目标，并依据期望收益选择系统动作[1]。Young 等进一步系统总结了 POMDP 对话系统的信念表示、状态监控和策略学习方法[2]。这类方法为“不确定条件下选择动作”提供了理论基础，但其状态空间和转移模型通常依赖受控领域，精确求解存在复杂度问题。

随着神经网络方法发展，对话状态跟踪逐渐从生成式贝叶斯模型转向判别式和文本生成式方法。TRADE 利用可迁移的槽值生成机制处理多领域状态跟踪[4]，TripPy 通过多源复制策略提高槽值提取能力[5]。Jacqmin 等的综述指出，现代 DST 在标准数据集上取得较大进展，但跨域泛化、状态一致性和真实部署中的不确定性仍未充分解决[3]。

现有 DST 研究主要回答“当前状态是什么”，而本研究进一步关注“状态与证据均不确定时应该采取什么动作”。因此，DST 和 POMDP 是本课题的理论基础，但不能直接解决 LLM 事实幻觉与证据可行性问题。

### 2.2 意图不确定性与澄清决策

澄清问题研究关注系统何时应提问、应该询问什么以及如何利用用户答复。Rahmani 等总结了会话澄清数据集、任务设置和评价指标，指出现有研究之间存在数据、实验设置和指标不一致的问题[6]。Feng 等提出面向任务型信息搜索的澄清框架和 ClariT 数据集，验证了结合任务知识与用户信息进行澄清的价值[7]。

在意图识别方面，den Hengst 等提出 CICC 方法，利用共形预测把分类器的不确定分数转换为包含真实意图的预测集，并根据预测集形成澄清问题[8]。该方法具有覆盖率层面的理论解释，但主要面向意图分类与单次澄清，未统一处理检索证据是否足以回答的问题。

Testoni 和 Fernández 研究了人类不确定性与模型不确定性对澄清行为的影响，发现模型不确定性并不总能复现人类的澄清选择[9]。Hu 等提出 Uncertainty of Thoughts，通过不确定性仿真、信息增益奖励和奖励传播选择主动提问，在诊断和故障排查任务中提高任务完成率[10]。Zhang 和 Choi 提出的 INTENT-SIM 通过模拟可能的用户意图与语义聚类估计歧义，用于决定何时需要澄清[11]。

上述研究证明“不确定时主动提问”具有价值，但多数方法重点优化信息增益、预测集覆盖或任务成功率。对于招聘场景，还需同时考虑：即使意图已明确，如果知识证据不足，系统仍不应对薪资、HC 或政策作出事实承诺。

### 2.3 大语言模型不确定性与幻觉检测

大语言模型可能生成语言流畅但缺乏事实依据的内容。Manakul 等提出 SelfCheckGPT，通过比较黑盒模型多次采样之间的一致性检测潜在幻觉，不要求访问模型内部概率[12]。该方法适合 API 场景，但多次采样会增加成本，而且“多次一致”不必然意味着事实正确。

Farquhar 等从语义等价类而非表面词序列计算语义熵，证明语义层面的不确定性能够识别一部分模型虚构[13]。语义熵为自由文本的不确定量化提供了重要工具，但其目标仍主要是检测而非动作决策。本课题拟将不确定性作为回答、澄清和拒答的决策输入，而不是只给回答附加一个风险分数。

### 2.4 检索增强生成与证据约束

Lewis 等提出检索增强生成（RAG），在生成过程中引入外部非参数知识，提高知识密集任务的可更新性和可追溯性[14]。后续研究分别从自反思检索、主动检索和评测等角度改进 RAG。例如 Self-RAG 通过检索与自反思标记调节生成[15]，FLARE 根据生成过程中的低置信内容触发主动检索[16]，RAGAS 等工作从忠实度、答案相关性和上下文相关性评估 RAG 管线[17]。

然而，RAG 并不天然保证真实性：检索可能失败，文档可能冲突，生成模型也可能忽略证据。许多工作在生成完成后检测或修正无依据陈述，而较少把“当前是否具备回答条件”直接纳入多轮动作选择。本研究所称“证据门控”不是简单增加检索，而是让证据充分度改变回答动作的可行性和风险。

### 2.5 招聘与职业对话研究

Hashimoto 等面向职业访谈提出基于 LLM 的动态槽生成方法，并引入溯因推理提高信息收集的灵活性和自然度[18]。Cao 等提出 SimRPD，利用用户模拟器、意图链和多维评价筛选招聘主动对话训练数据，在真实招聘业务中验证方法价值[19]。这些研究说明招聘对话具有明确的流程目标、意图序列和真实数据基础，但其重点分别是槽位生成和训练数据选择。

招聘相关研究还必须关注透明度、公平性和人类监督。对话系统不应基于性别、年龄等受保护属性作出差异化录用判断。本课题只优化咨询对话的理解与事实可靠性，并通过数据最小化、脱敏、审计日志和人工接管控制伦理风险。

### 2.6 文献评述与研究缺口

现有工作已经分别形成四条成熟研究线：

1. POMDP/DST：维护对话状态与不确定性；
2. 澄清决策：在歧义或信息不足时主动提问；
3. 不确定性/幻觉检测：识别黑盒 LLM 的潜在错误；
4. RAG/证据归因：利用外部文档支持生成。

因此，本课题不能把“引入信念状态”“加入澄清”或“使用 RAG”单独宣称为创新。当前可进一步研究的缺口是：

> 现有方法通常把意图澄清和事实依据分开优化，缺少在多轮条件下将意图信念、证据充分度及答错、追问、拒答等不对称代价统一到一个动作决策目标中的方法，尤其缺少在脱敏招聘业务数据上的算法级对比与消融验证。

该缺口仍需在开题提交前通过不少于 40 篇文献的系统检索继续验证，避免与 2025—2026 年最新工作高度同构。

## 三、研究目标、问题与假设

### 3.1 总体目标

提出一种面向招聘多轮对话的证据门控风险敏感决策算法（Evidence-Gated Risk-Sensitive Decision，EG-RSD），在黑盒 LLM API 条件下统一选择回答、澄清或拒答/转人工，并在脱敏招聘数据上验证其可靠性、交互效率与业务适用性。

### 3.2 具体目标

1. 构建招聘多轮对话的意图空间、事实风险类型、动作集合和业务代价模型；
2. 研究黑盒 API 条件下的多轮意图信念估计与校准方法；
3. 设计决策前证据充分度判断与生成后原子事实核验机制；
4. 提出回答—澄清—拒答的统一风险决策算法与一轮前瞻澄清策略；
5. 构建脱敏评测集、强基线与人工评测协议，完成主实验、消融和敏感性分析；
6. 推导至少一个决策边界或单调性命题，解释算法行为。

### 3.3 研究问题

- **RQ1**：黑盒 LLM 的多次采样、结构化打分与共形校准能否形成可靠的意图信念？
- **RQ2**：把证据充分度纳入动作可行域和风险函数，能否比“检索后直接回答”更有效地控制事实幻觉？
- **RQ3**：业务代价驱动的动态决策能否比固定置信阈值减少高风险误答，同时避免过度澄清？
- **RQ4**：该方法在不同意图、不同风险类型和不同 API 模型上是否稳定？

### 3.4 研究假设

- **H1**：在相同任务成功率下，EG-RSD 的累计风险显著低于固定阈值澄清与 Naive RAG；
- **H2**：在相同事实幻觉率上限下，EG-RSD 的平均澄清轮数低于仅依赖不确定度的澄清策略；
- **H3**：多轮信念更新在意图漂移、指代和多意图测试集上优于逐轮独立分类；
- **H4**：证据门控对薪资、岗位状态和招聘政策等高风险事实问题的收益高于一般性交流问题。

## 四、研究内容

### 4.1 招聘多轮对话状态与风险建模

定义招聘意图、槽位、对话阶段和事实类型。根据脱敏业务日志构建意图转移关系，区分普通信息错误与高风险事实错误。通过历史频率、业务专家成对偏好和敏感性分析确定代价的相对大小，避免只凭研究者主观指定参数。

### 4.2 多轮意图信念估计与校准

利用对话历史、当前话轮和意图转移先验形成候选意图分布。若 API 不提供可靠 logits，则采用结构化候选打分、多次采样投票、语义聚类或共形预测集近似不确定性，并使用独立校准集评估 ECE 与覆盖率。

### 4.3 证据检索、充分度计算与双层门控

从岗位、JD、流程和政策等知识源检索候选证据。决策前判断证据是否覆盖当前问题所需的事实槽位；生成后将回答拆分为原子事实，检查每项事实是否能映射到证据 ID 和文本片段。对证据不足或冲突的事实，不允许模型通过常识补写。

### 4.4 风险敏感动作决策

把意图误判、事实幻觉、澄清交互和拒答转人工等代价放入统一目标。计算回答、候选澄清问以及拒答动作的期望风险，选择风险最小的可行动作。澄清动作采用一轮前瞻估计其预期风险下降，而不是只依据固定置信阈值。

### 4.5 业务旁路接入与迭代验证

算法先作为旁路层接收现有意图、检索和候选回答结果，只记录建议动作而不直接影响用户；完成离线和影子验证后，再根据合规条件决定是否开展小流量对照。新日志经脱敏、标注和错误归因后，用于更新校准参数、代价矩阵和证据阈值。

## 五、算法设计与形式化

### 5.1 状态、信念与动作

在第 \(t\) 轮，记：

- 对话历史为 \(h_t\)，当前输入为 \(u_t\)；
- 隐含真实意图为 \(z_t\in\mathcal{Z}\)；
- 意图信念为 \(b_t(z)=P(z_t=z\mid h_t,u_t)\)；
- 检索证据集合为 \(\mathcal{E}_t\)；
- 证据充分度为 \(s_t\in[0,1]\)；
- 动作集合为

\[
\mathcal{A}
=\{\operatorname{answer},
\operatorname{clarify}(q),
\operatorname{refuse/handoff}\}.
\]

### 5.2 意图信念更新

\[
b_t(z)\propto
\ell_{\mathrm{API}}(u_t,h_t\mid z)
\sum_{z'}T(z\mid z')b_{t-1}(z'),
\]

其中，\(T(z\mid z')\) 为脱敏历史对话估计的意图转移概率，\(\ell_{\mathrm{API}}\) 为 API 对当前输入属于候选意图的近似似然。实际实现中将比较多次采样、结构化打分与共形预测等方案。

### 5.3 证据充分度

证据充分度暂定义为检索相关性、事实蕴含性和需求覆盖度的组合：

\[
s_t
=\alpha r_t+\beta e_t+\gamma c_t,
\qquad
\alpha+\beta+\gamma=1,
\]

其中 \(r_t\) 表示文档与问题的相关性，\(e_t\) 表示证据对候选事实的支持程度，\(c_t\) 表示所需事实槽位的覆盖程度。具体组合方式将在校准集上确定，并通过人工标注进行验证。

### 5.4 动作风险

回答动作风险：

\[
J_{\mathrm{ans}}
=c_i\big(1-b_t(\hat z)\big)
+c_f(1-s_t)
+c_vV_t,
\]

其中 \(V_t\) 表示问题的业务敏感等级。

澄清动作风险：

\[
J_{\mathrm{clarify}}(q)
=c_q+
\mathbb{E}_{y\sim P(y\mid q,h_t)}
\left[\min_{a}J_{t+1}(a\mid y)\right].
\]

拒答或转人工动作风险：

\[
J_{\mathrm{handoff}}=c_h+c_{\mathrm{delay}}.
\]

最终决策为：

\[
a_t^\star=
\arg\min_{a\in\mathcal{A}_{\mathrm{feasible}}(\mathcal{E}_t)}
J_t(a).
\]

对事实型高风险问题，当 \(s_t<\tau\) 时，回答动作从可行动作集合中剔除，或给予足够大的风险惩罚。

### 5.5 算法伪代码

```text
Algorithm EG-RSD
Input: dialogue history h_t, utterance u_t, intent set Z,
       knowledge base K, cost parameters C
Output: response action and response text

1. q_t ← APIIntentCandidates(h_t, u_t, Z)
2. b_t ← CalibratedBeliefUpdate(b_(t-1), q_t, transition T)
3. E_t ← RetrieveEvidence(K, h_t, u_t, b_t)
4. s_t ← EvidenceSufficiency(E_t, required facts)
5. Q_t ← GenerateCandidateClarifications(b_t, missing facts)
6. Compute J_answer, J_handoff
7. For q in Q_t:
       estimate one-step J_clarify(q)
8. A_feasible ← EvidenceGate(A, s_t, risk type)
9. a_t ← argmin_(a∈A_feasible) J_t(a)
10. If a_t = answer:
       draft ← GenerateGroundedAnswer(E_t)
       response ← AtomicClaimVerify(draft, E_t)
    Else if a_t = clarify:
       response ← selected clarification q*
    Else:
       response ← safe refusal or human handoff
11. Log belief, evidence IDs, risks, action and outcome
```

### 5.6 拟分析的算法性质

1. **回答区域单调性**：当其他条件不变时，幻觉代价增加或证据充分度降低，最优策略的回答区域不应扩大；
2. **门控安全性**：当证据低于阈值且无据回答代价大于澄清/拒答代价时，最优动作不选择无据回答；
3. **固定阈值退化关系**：在忽略证据项、令各类问题代价相同且不做前瞻时，算法退化为固定置信阈值策略。

这些性质目前属于待推导命题，正式开题时只陈述研究计划，不提前宣称已经证明。

## 七、实验方案

### 7.1 数据来源与合规

数据由企业招聘咨询对话、岗位知识与流程文档构成。原始姓名、手机号、邮箱、微信号、身份证、精确公司/岗位敏感字段及可反推个体身份的信息必须删除、泛化或映射。研究仓库只保存脱敏数据说明、统计量和匿名证据 ID，不保存原始敏感对话。

数据按时间、岗位或业务单元切分训练/校准/测试集，避免同一会话、相似模板或同一知识片段跨集合泄漏。正式使用前需获得公司书面或可追溯授权，并确认学院是否要求伦理审查。

### 7.2 标注任务

每段样本至少标注：

1. 当前主意图与次意图；
2. 是否存在意图漂移、指代或信息缺失；
3. 当前是否应澄清；
4. 可接受的澄清问题要点；
5. 回答需要的证据 ID；
6. 候选回答中的事实是否获得证据支持；
7. 风险类型与严重度；
8. 最终任务是否完成。

抽取双人标注子集计算一致性（如 Cohen’s \(\kappa\)），争议样本由业务专家仲裁。

### 7.3 数据规模规划

- 大规模未精标脱敏日志：用于统计意图转移与错误分布；
- 精标开发/校准/测试集：先完成可复现的小规模集合，再根据一致性和统计功效扩展；
- 压力测试集：专门覆盖多意图、话题切换、指代、知识缺失、冲突证据及诱导承诺等场景。

在获取真实数据统计前，不在开题中虚构总样本量；提交前需补充可获得规模和类别分布。

### 7.4 对比基线

1. 裸 LLM 多轮对话；
2. Greedy Intent + Generate；
3. Fixed-threshold Clarification；
4. CICC 或等价的共形意图澄清；
5. UoT / INTENT-SIM 类不确定感知澄清；
6. Naive RAG；
7. RAG + SelfCheckGPT；
8. 现有业务策略。

### 7.5 消融实验

- EG-RSD w/o Belief：去掉多轮信念，只使用当前轮意图；
- EG-RSD w/o Risk：改为固定阈值；
- EG-RSD w/o EvidenceGate：检索后直接回答；
- EG-RSD w/o Lookahead：不计算澄清后的期望风险；
- Soft Gate vs Hard Gate：证据风险惩罚与硬约束对比。

### 7.6 评价指标

| 维度 | 指标 |
|------|------|
| 意图 | Accuracy、Macro-F1、意图漂移子集准确率 |
| 校准 | ECE、Brier Score、共形覆盖率与预测集大小 |
| 证据 | Retrieval Recall、Citation Precision/Recall、事实支持率 |
| 幻觉 | Unsupported Claim Rate、高风险事实错误率 |
| 对话 | Task Success、Clarification Precision、平均澄清轮数 |
| 综合 | 累计风险、风险—成功率曲线、选择性回答曲线 |
| 业务 | 用户纠正率、转人工率、会话中断率、问题解决率 |

业务转化率受岗位供需、渠道和用户质量等混杂因素影响，只作为辅助指标，不能代替算法评价。

### 7.7 统计分析

- 对比例或准确率采用 bootstrap 置信区间或配对检验；
- 对同一测试集上的决策差异采用 McNemar 检验；
- 对澄清轮数、累计风险等非正态指标采用配对非参数检验；
- 报告效果量和置信区间，不只报告 \(p\) 值；
- 对代价系数、证据阈值、检索数量和 API 模型进行敏感性分析。

### 7.8 业务验证

1. **离线回放**：在固定测试集上运行全部算法；
2. **影子模式**：新算法只输出建议，不影响用户，比较其建议与现网结果；
3. **人工审核**：业务专家抽检高风险样本；
4. **小流量验证**：仅在公司审批、隐私和回退机制完备时开展；
5. **反馈回灌**：将新失败样本脱敏、归因后加入下一轮评测。

## 八、拟解决的关键问题

1. **黑盒 API 的不确定信号是否可信**：通过独立校准集、共形覆盖和多种不确定估计对比解决；
2. **证据充分度如何客观计算**：结合检索相关性、事实蕴含、槽位覆盖和人工标注，避免只让同一 LLM 自我评价；
3. **业务代价如何避免主观化**：结合错误发生频率、业务专家成对排序及参数敏感性分析；
4. **澄清收益如何离线评估**：使用真实后续回复、受控用户模拟与人工评测交叉验证；
5. **如何证明不是模块拼接**：以统一风险目标、可行动作集合、决策边界性质和消融实验呈现算法贡献。

## 九、创新点

### 创新点一：证据门控的风险敏感多轮动作决策

提出把多轮意图信念、证据充分度以及误答、幻觉、澄清和拒答代价纳入统一风险函数的方法，使证据条件直接改变回答动作的可行性与最优决策边界。相较于只优化信息增益的澄清方法或生成后的幻觉检测，本研究在回答前统一决定“是否应当回答”。

### 创新点二：面向招聘高风险事实问答的业务代价建模与闭环验证

构建招聘对话的风险类型、证据标注和不对称代价协议，将脱敏业务日志映射为意图转移、校准数据、风险参数和业务回归指标，并通过离线回放、影子验证、强基线与消融实验评价算法。

> 多轮意图信念更新暂作为算法组件，不单独宣称创新；只有在后续证明相对 DST/CICC 有明确新机制和独立收益时，才升级为第三创新点。

| 风险 | 影响 | 应对措施 |
