## 1. 一句话结论

国内软工 / AI / 大模型硕博选题高度同构，主流是：

**垂直场景 +（意图/检索/图谱/多智能体）模块改进 + 系统实现与业务验证**

真正接到经典学习理论（拒答 / 选择性预测 / 序贯决策最优规则）的很少；多数“算法升级”= 流水线模块增强，而非新决策准则。

## 2. 六大方向簇（按出现频率）

### A. 检索增强生成（RAG）+ 领域问答（最热）

| 常见切口 | 所谓“算法升级” | 典型场景 |
|----------|-----------------|----------|
| 分块 / 混合检索 / 重排 | 主题树检索、图引导检索、查询重写 | 校园、电力、政务、应急预案 |
| 抗幻觉 | 证据完备性评估、早停生成 | 专业规程问答 |
| 本地 / 隐私部署 | 云地混合 LLM + RAG | 警务、企业手册 |

**范式**：`领域语料 → 向量库/图谱 → RAG → 评测 EM/F1/BERTScore`

### B. 意图识别 + 任务型对话 / 智能客服

| 常见切口 | 所谓“算法升级” | 典型场景 |
|----------|-----------------|----------|
| 单轮/多轮意图分类 | BERT/TextCNN/轻量微调；LLM 标注蒸馏小模型 | 电商客服、校园、政务 |
| 意图冲突 / 话题切换 | 规则库 + 图神经网络 / 置信度阈值 | 多轮客服 |
| 澄清触发 | 置信度低于阈值则追问（工程阈值，少理论） | 生产对话系统 |

**与本课题最近**：已有“低置信 → 澄清”工程实践，但很少写成**带证据约束与不对称代价的最优动作选择**。

### C. 知识图谱 × 大模型融合

| 常见切口 | 所谓“算法升级” | 典型场景 |
|----------|-----------------|----------|
| KG 构建 / 抽取 | BERT-BiGRU-CRF、事理图谱、LLM 辅助抽取 | 燃气应急、装备管理、交通 |
| KG 增强生成 | 子图检索 + Prompt 注入；PCST 剪枝 | 医疗 / 专业 QA |
| Text2Cypher / 模板问答 | 意图 → 查询模板 → 图谱答案 | 工业规程 |

### D. 多智能体（Agent）协作问答

| 常见切口 | 所谓“算法升级” | 典型场景 |
|----------|-----------------|----------|
| 任务分解多智能体 | 实体/意图/检索/证据反馈/生成分角色 | 电力安规 |
| 自适应闭环 RAG | Grader 评估证据 → 查询重写 → 再检索 | 多跳开放域 QA |
| 争议解决 / 迭代讨论 | 多智能体辩论降幻觉 | 领域问答 |

### E. 参数高效微调与领域适配

| 常见切口 | 所谓“算法升级” | 典型场景 |
|----------|-----------------|----------|
| LoRA / P-Tuning / PEFT | 领域语料微调 + RAG/KG | 企业装备、工业手册 |
| 数据闭环 | HITL 校正 → 再微调 | 本地 QA 生成器 |

### F. 软件工程视角的“系统型”论文（学院常见）

| 常见切口 | 贡献形态 | 注意 |
|----------|----------|------|
| 需求分析 → 架构 → 实现 → 测试 | 原型系统 + 用例验证 | 算法深度弱，易被导师判为“工程堆砌” |
| 隐私 / 部署 / 性能 | 混合云端、延迟与准确权衡 | 适合专硕，学术型需补理论 |
| 评测体系 | LLM-as-Judge、领域数据集构建 | 可作辅助贡献，不宜单独撑题 |

## 3. 「算法升级 + 应用」论文的真实贡献层级

国内同类论文自述创新，大多落在下面 4 层（从弱到强）：

1. **工程组装层**：LangChain/Dify + 向量库 + 业务前端（硕士常见，创新弱）
2. **模块改进层**：检索重排、意图路由、查询重写、图谱子图剪枝（最常见可过线层）
3. **机制设计层**：多智能体闭环、证据充分性门控、置信度触发澄清（较强，但仍偏系统）
4. **决策理论层**：把回答/澄清/拒答写成风险最优规则，并给出退化/单调性命题（**稀缺**；本课题目标层）

> 开题表述建议：明确站在第 4 层，应用（招聘）只作验证域，避免被归入第 1–2 层“又一个 RAG 客服”。

## 5. 与本课题（UB-CEG / EG-RSD）对照

| 国内主流 | 本课题差异点 |
|----------|--------------|
| 意图分类准确率为主指标 | 以**回答/澄清/拒答动作代价**与风险曲线为主 |
| 阈值澄清多为工程经验 | 目标写成 **Chow 拒答规则的多轮+澄清推广** |
| RAG 证据用于生成 | 证据用于**门控动作可行域**，不只拼 Prompt |
| 场景驱动“做系统” | 场景（招聘）驱动**验证算法**，系统为载体 |
| 少理论命题 | 拟证 P1–P4（安全门控、退化、单调、风险–澄清权衡） |

**可借鉴点（写相关工作时）：**

- 意图路由 + RAG 的流水线组织（作强基线，而非创新本体）
- 多智能体中的“证据充分性评估/早停”思想（可映射为门控信号）
- 置信度触发澄清的生产经验（说明问题真实，但缺最优准则）
- 领域数据构建与脱敏评测方法（招聘数据协议可参考）
