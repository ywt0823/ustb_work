# 业务问题定义（招聘验证域）

> 招聘是**验证场景**，不是论文边界。通用问题见 [[01-论文/选题/选题锁定-v3-通用问题招聘验证]]。

## 场景

58 招聘 B 端智能代聊：求职者发起咨询，HR 不在线时由 AI 接管。

三核心任务（策略不同）：

1. **人岗匹配**——条件与职位要求比对
2. **留资引导**——沉淀联系方式/简历线索
3. **答疑**——薪资、地点、岗位要求等事实问答

架构背景：中控 Agent（意图分发）+ 专项 Agent；底座为自研 ChatLing；规模约 12K 会话/分钟。

## 痛点 → 通用算法变量

| 业务现象 | 通用问题 | 算法变量 |
|----------|----------|----------|
| 意图分发错误 / 假自信 | 意图部分可观测 | 信念 \(b_t\)，非硬标签 |
| 「96的」等口语槽位歧义 | 槽位不确定 | 槽位置信 / 歧义分 \(z_t\) |
| RAG 未命中仍编造答疑 | 证据不充分仍执行 | 证据充分度 \(e_t\) |
| 匹配错 / 过早要电话 / 乱答 | 多目标不对称代价 | 代价矩阵 \(C\) |
| action=调用工具或追问 | 执行 vs 澄清 | 动作集 {EXECUTE, CLARIFY, ABSTAIN} |
| 弱模型 + 工程补效果 | 黑盒 LLM 外层决策 | 仅 API/调用，不改基座 |

## 约束

- 数据丰富，必须脱敏后方可入实验/论文
- 推理侧以模型调用为主（内部 ChatLing / API）
- 需要可量化业务指标回归验证
- 论文贡献不得写成平台实现说明
