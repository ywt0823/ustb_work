## 一、选题名称

**建议题目：**  
基于意图信念更新与证据门控的风险敏感多轮对话决策算法——以招聘场景为例

**英文（可选）：**  
Risk-Sensitive Multi-turn Dialogue Decision-Making with Belief Tracking and Evidence Gating: A Case Study in Recruitment Conversations

---

## 二、研究背景与意义

### 2.1 背景

大语言模型（LLM）使任务型对话系统快速进入招聘等业务场景，用于岗位咨询、流程问答、候选人引导等。然而在真实多轮交互中，仍普遍存在三类问题：

1. **意图识别不稳**：指代、话题切换、一语多意导致误判；  
2. **对话衔接断裂**：系统「假懂」后直接回答，缺少必要澄清；  
3. **事实幻觉**：对薪资、编制、流程、政策等作出无依据承诺。

上述问题在招聘场景中代价不对称：一次错误事实承诺的信任与合规成本，往往远高于多问一轮澄清的体验成本。现有工业实践多依赖 Prompt、工作流编排或单点 RAG，**缺少将意图不确定、澄清决策与证据约束统一到同一算法目标下的方法**。

同时，受部署与合规约束，本课题假设**仅能调用 LLM API、不改基座权重**，因此研究重点必须放在**可插拔的外层决策算法**，而非预训练结构革新。

### 2.2 意义

- **理论/方法意义**：将招聘多轮对话建模为部分可观测意图下的序贯决策问题，把证据可行性嵌入动作空间与风险，形成可计算、可消融的决策算法框架。  
- **应用意义**：在脱敏业务对话上验证能否降低误答与幻觉、提升任务成功率，服务真实招聘交互质量。  
- **工程约束下的研究价值**：证明在黑盒 API 条件下仍可做出清晰的算法贡献，符合「理论联系实际」。

## 三、国内外研究现状

（写作时展开为 3–5 页；此处给逻辑骨架与代表工作。）

### 3.1 任务型对话与状态跟踪

经典任务型对话将对话管理建模为 MDP/POMDP，并以 Dialogue State Tracking（DST）维护槽位与目标。该类工作理论完整，但在开放语义与 LLM 生成时代，需要与大模型推理模块重新结合。

### 3.2 不确定感知与澄清问生成

- **CICC**：共形预测将意图不确定转为预测集并生成澄清问，具有覆盖保证。  
- **INTENT-SIM**：通过模拟意图响应估计歧义，决定何时澄清。  
- **UoT**：以不确定仿真与信息增益规划主动提问。  
- **SAGE-Agent 等**：结构化不确定 + EVPI/POMDP 式澄清。  

**不足：** 多聚焦「问得是否有效」，对「回答是否允许（证据是否足够）」与业务不对称代价建模不足；招聘多轮意图漂移场景验证少。

### 3.3 幻觉检测与证据约束生成

Semantic Entropy、SelfCheckGPT、RAG attribution 与 evidence-grounded generation 等，从检测或检索约束角度降低幻觉。  

**不足：** 常作为生成后处理或单轮 QA 管线，**很少进入多轮动作选择的统一风险目标**。

### 3.4 招聘领域对话

SimRPD、职业面试动态槽系统等表明招聘对话有明确业务目标与数据特点，但创新多在数据构造、主动对话策略或系统实现，**算法层面的不确定决策与证据门控耦合仍不充分**。

### 3.5 综述结论与课题切入点

澄清、不确定量化、证据约束各自成熟；缺口在于：

> **在高误答/幻觉代价的多轮招聘对话中，如何将意图信念、澄清/拒答/回答与证据可行性纳入同一风险敏感决策算法，并在仅 API 条件下可实现、可验证。**

对比表见 [[02-文献/对比表/相关工作对比表-v0]]。

## 四、研究目标

### 4.1 总体目标

提出一种面向招聘多轮对话的**证据门控风险敏感决策算法**，在黑盒 LLM API 条件下实现意图信念更新、澄清动作选择与证据约束应答，并在脱敏业务数据上相对强算法基线验证有效性。

### 4.2 具体目标

1. 建立招聘多轮对话的形式化模型（信念、动作、风险、证据约束）；  
2. 设计可实现算法（信念更新、风险动作选择、证据门控解码）及伪代码；  
3. 构建脱敏评测集与标注协议，完成对比与消融实验；  
4. 给出至少一项策略性质讨论（简化假设下），支撑「算法革新」表述。

## 五、研究内容与关键问题

### 5.1 研究内容一：意图信念估计与多轮更新

- 受控意图空间与槽位设计（招聘领域）；  
- 基于 API 的候选意图似然/语义相似估计；  
- 信念 \(b_t\) 更新与不确定度（熵/共形集大小/语义不确定）；  
- 处理意图漂移与指代。

**关键问题：** 如何在黑盒 API 下得到可用于决策的可靠不确定信号？

### 5.2 研究内容二：风险敏感动作选择（主创新承载点）

- 动作：回答 / 澄清 / 拒答（转人工或声明未知）；  
- 定义不对称代价 \(R(a,z)\)（误答、幻觉、澄清、拒答）；  
- 以期望风险（可加澄清成本）选择动作；  
- 澄清内容由预测集或高不确定槽位驱动生成。

**关键问题：** 如何设计可计算的风险准则，使其优于固定阈值与纯信息增益策略？

### 5.3 研究内容三：证据门控与约束生成

- 检索证据子集 \(\mathcal{E}_t\)；  
- 支持度评估；不足则禁止事实性承诺；  
- 有据回答需可追溯引用；可叠加 SelfCheck 类一致性检查。

**关键问题：** 如何将证据约束嵌入决策（可行动作集/风险惩罚），而非仅事后过滤？

### 5.4 研究内容四：实验验证与分析

- 强基线与消融；  
- 自动指标 + 人工评测；  
- 失败案例分析（仍幻觉、过度澄清、信念崩塌等）。

## 六、研究方法与技术路线

### 6.1 方法思路

将 LLM API 视为语义推理器 \(f_\theta\)，自研算法负责任意时刻的决策：

```text
u_t, h_t
   │
   ▼
BeliefUpdate  →  b_t, u(b_t)
   │
   ├─ Retrieve → E_t, supp
   │
   ▼
RiskSensitiveAct(b_t, supp, costs)
   │
   ├─ clarify → 生成澄清问 → 更新历史
   ├─ refuse  → 拒答/转人工
   └─ answer  → EvidenceGateDecode(E_t) → 有据应答
```

算法草案：[[03-算法/自研算法/ALG-UB-CEG-草案]]

### 6.2 技术路线图（文字版）

1. **问题调研与形式化** → 符号体系、代价表  
2. **数据脱敏与标注规范** → 意图/澄清必要性/证据 ID  
3. **模块实现** → 信念 / 决策 / 证据门（API 调用封装）  
4. **基线复现** → CICC 或阈值澄清、UoT/INTENT-SIM 类、RAG、裸多轮  
5. **主实验 + 消融 + 人工评测**  
6. **性质讨论与论文撰写**

### 6.3 拟解决的关键问题（开题常用三问）

1. 黑盒条件下不确定度估计的有效性与校准；  
2. 不对称风险下澄清—回答—拒答的统一决策；  
3. 证据门控与多轮信念的耦合，避免「有检索仍乱答 / 无检索仍敢答」。

## 七、实验方案与评价指标

### 7.1 数据

- 来源：招聘业务多轮对话（脱敏，见 [[04-业务/数据与脱敏/脱敏原则]]）；  
- 规模：先建精标测试集（建议 300–800 段，可分期扩展）；  
- 标注：意图、是否应澄清、金标准证据、可否事实回答。

### 7.2 基线

1. 裸 LLM 多轮；  
2. Greedy Intent + Generate；  
3. Fixed-threshold Clarification；  
4. CICC（或同类共形澄清）；  
5. UoT / INTENT-SIM 类主动澄清；  
6. Naive RAG；  
7. SelfCheckGPT 后处理。

### 7.3 消融

w/o Belief；w/o Risk；w/o EvidenceGate。

### 7.4 指标

Intent Acc、ECE、Task Success、Clarification Quality、Hallucination Rate、Coherence、Avg Clarification Turns、Cumulative Risk。  
详见 [[04-业务/评价指标/指标草案]]、[[05-实验/方案/EXP-主实验协议-v0]]。

### 7.5 模型冻结

记录 API 模型名与版本；主结果固定一套；附录做 1–2 个模型敏感性。

## 八、创新点（建议只写 2 条，最多 3 条）

1. **（主）证据门控的风险敏感多轮对话决策算法**：将意图信念、澄清/回答/拒答与证据可行性纳入统一期望风险目标，给出可实现算法流程；相对信息增益型澄清与后处理式抗幻觉具有明确决策机制差异。  

2. **（辅）面向招聘高代价误答场景的形式化与验证协议**：定义不对称代价与评测协议，在脱敏真实对话上相对多种算法基线完成对比与消融，并讨论简化假设下的策略性质。  

（可选第 3 点，慎加）多轮意图漂移下的信念更新策略设计——仅当有清晰相对 DST/单轮 CICC 的算法差异时再写。
