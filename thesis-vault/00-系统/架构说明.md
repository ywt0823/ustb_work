# 架构说明

## 1. 设计目标

本库不是普通笔记堆，而是三条线并行的**可扩展生产系统**：

1. **论文生产线**：从选题到实验到成稿
2. **研究知识线**：文献、算法、业务、实验证据可回溯
3. **产品/IP 生产线**：记录人机协作全过程，沉淀方法论与可产品化素材

结构刻意对齐 Obsidian 习惯：**文件夹分层 + Markdown + YAML 前置元数据 + `[[双链]]` + `#标签` + MOC（内容地图）**。

## 2. 总体拓扑

```text
thesis-vault/
├── 00-系统/          # 元规则（怎么用库）
├── 01-论文/          # 论文主产物
├── 02-文献/          # 输入：他人工作
├── 03-算法/          # 输入→自研：方法资产
├── 04-业务/          # 问题域与约束
├── 05-实验/          # 证据与结果
├── 06-AI协作日志/    # 过程资产（IP 原料）
├── 07-产品IP/        # 产品化输出
├── 08-资源/          # 外链与工具
├── 09-归档/          # 废弃但不删除
├── Templates/        # 模板
├── Daily/            # 日记/短记录
└── Attachments/      # PDF/图/数据说明附件
```

## 3. 信息流向（写作时按此流动）

```text
业务痛点(04) ──► 选题/开题(01)
                      │
文献(02) ─────────────┼──► 方法/算法(03) ──► 实验(05) ──► 论文正文(01)
                      │
AI会话(06) ───────────┴──► 决策固化 ──► 产品方法论(07)
```

原则：

- **事实与证据**进 `02/03/04/05`
- **过程与思考**进 `06`
- **可对外卖的方法论**进 `07`
- **最终学术表述**进 `01`

避免把聊天原文直接当论文段落；会话要先「提炼」再「入库」。

## 4. Obsidian 机制怎么用

| 机制 | 本库约定 |
|------|----------|
| 双链 `[[笔记名]]` | 概念、论文、算法、决策互相链接 |
| MOC | 每个一级域有一张总览地图 |
| Frontmatter | 统一 `type / status / tags / sources` |
| 标签 | 检索维度，见 [[00-系统/标签体系]] |
| Daily Notes | 当日碎片想法、待办 |
| Templates | 新建文献/会话/决策必须套模板 |
| Graph View | 检查「孤立笔记」与主题聚类 |
| Canvas（可选） | 开题技术路线、产品信息架构草图 |

## 5. 扩展策略（你后续会逐渐长出来）

| 阶段 | 重点扩展目录 | 完成标志 |
|------|--------------|----------|
| P0 选题锁定 | 01/选题, 06/会话与决策 | 导师确认题目 |
| P1 文献综述 | 02 核心论文 ≥15, 对比表 | 国内外现状章节可写 |
| P2 方法成型 | 03 自研算法伪代码 + 形式化 | 可答辩的算法贡献点 |
| P3 实验闭环 | 04 脱敏方案 + 05 结果 | 主表与消融表齐备 |
| P4 论文成稿 | 01 写作各章 | 初稿→终稿 |
| P5 产品化 | 07 方法论与案例 | IP 大纲/内容矩阵 |

新增笔记时：**先判断它服务哪条线**，再放入对应编号目录，并回链到所属 MOC。

## 6. 与 Git 仓库的关系

- Vault 位于仓库根下：`thesis-vault/`
- 建议每次重要会话或论文增量后 commit
- 敏感业务原文、未脱敏数据 **禁止** 入库；只放脱敏说明与指标定义
