# DEC · 选题收束 · 通用问题 + 招聘验证

## 触发

用户补充智能招聘 Agent 平台详情，并提出：只面向招聘偏窄，应以招聘为素材探索普遍对话研究方向。

## 决策

1. **论文问题通用化**：多目标任务型对话中的证据约束风险敏感序贯决策（执行/澄清/弃权）
2. **招聘降为验证域**：58 智能代聊 Agent 提供数据、协议变量与业务代价实例化
3. **不把系统架构当创新**：中控+专项 Agent、RAG、Few-shot、拟人度均作工程背景/基线
4. **保留底层算法根**：Reject-Option / Selective Prediction 的多轮澄清推广

## 不做什么

- 不以「招聘 Agent 平台设计与实现」作主贡献
- 不主攻拟人度 / Prompt 工程
- 不主攻多智能体通信协议本身
- 不把 LoRA/基座训练写入创新（与 API/内部模型调用约束不符）

## 影响

- 题目改为「通用方法——以智能招聘代聊为例」
- 国内外现状需同时覆盖：任务型对话策略、拒答/选择性预测、澄清/主动信息获取；招聘仅作应用节
- 实验需至少 1 个非招聘迁移验证（公开任务型对话集或合成多目标对话），证明不只贴招聘
